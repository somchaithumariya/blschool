# ระบบบริหารจัดการโรงเรียน: Apps Script MVP

โครงการนี้เป็น Google Apps Script Web App ระยะเริ่มต้น ประกอบด้วยหน้าเข้าสู่ระบบ ระบบ session และสิทธิ์ตามบทบาท แดชบอร์ด ศูนย์รวมแอป 36 รายการ การตั้งค่าข้อมูลโรงเรียนและสถานะโมดูล ตลอดจนชั้นจัดเก็บข้อมูล Google Sheets ที่สร้างโครงสร้างได้โดยไม่ลบข้อมูลเดิม

## ขอบเขตที่ใช้งานได้ในรุ่นนี้

- เข้าสู่ระบบ ออกจากระบบ เปลี่ยนรหัสผ่าน และตรวจ session ที่ฝั่งเซิร์ฟเวอร์ บัญชีที่ใช้รหัสผ่านเริ่มต้นถูกจำกัดให้เปลี่ยนรหัสผ่านหรือออกจากระบบเท่านั้น
- บทบาทเริ่มต้น ได้แก่ ผู้ดูแลระบบ ครู และผู้บริหาร พร้อมสิทธิ์ระดับเมนูและการกระทำ
- Dashboard แสดงจำนวนบุคลากร นักเรียน ห้องเรียน และโมดูลที่ผู้ใช้เข้าถึงได้
- ศูนย์รวมแอปและเส้นทางครบ 36 รายการ แบ่งเป็น 9 หมวด
- ผู้ดูแลระบบแก้ชื่อโรงเรียน คำอธิบาย รหัสไฟล์โลโก้ สีหลัก ข้อความท้ายหน้า และเปิดหรือปิดโมดูลได้
- `setupSystem()` ตรวจว่า `FILES_FOLDER_ID` เปิดได้ แล้วสร้าง Sheet และ header ที่ขาดแบบ idempotent
- `seedSystem()` เพิ่มบทบาท สิทธิ์ โมดูล การตั้งค่า และบัญชีผู้ดูแลเมื่อยังไม่มีข้อมูล โดยเรียกซ้ำได้หลังลบ password เริ่มต้น
- การเข้าสู่ระบบจำกัดความยาวข้อมูล ใช้ตัวนับรายบัญชีและ token bucket ระดับระบบภายใต้ ScriptLock พร้อม backoff โดยไม่เพิ่มแถว log ทุกครั้งที่รหัสผ่านผิด
- การเขียนข้อมูลใช้ repository กลาง, lock, optimistic version และ AuditLogs การเปลี่ยน settings/modules กับ audit commit เป็นชุดเดียวและ rollback เมื่อเกิดข้อผิดพลาด

โมดูลข้อมูลบุคลากร นักเรียน ห้องเรียน ตารางสอน การเช็กชื่อ รายงาน และโมดูลเอกสารในระยะนี้มีเฉพาะ schema สิทธิ์ เมนู และเส้นทาง หน้าเว็บจะแสดง “อยู่ระหว่างพัฒนา” และไม่มีปุ่มบันทึกข้อมูล จึงไม่ควรนำไปใช้บันทึกข้อมูลจริงจนกว่าจะพัฒนาบริการและหน้าจอของแต่ละโมดูลเสร็จ

## 1. เตรียม Google Sheet และโฟลเดอร์ Drive

1. สร้าง Google Sheet ใหม่สำหรับฐานข้อมูล และคัดลอก Spreadsheet ID จาก URL
2. สร้างโฟลเดอร์ Google Drive สำหรับโลโก้ รูป และเอกสาร แล้วคัดลอก Folder ID
3. จำกัดสิทธิ์ของทั้งสองรายการให้เฉพาะเจ้าของระบบและผู้ดูแลที่จำเป็น ไม่ตั้งค่าเป็นสาธารณะ
4. สำรองข้อมูล Google Sheet ก่อนปรับ schema หรืออัปเดตโค้ดในครั้งถัดไป

## 2. กำหนด Script Properties

เปิด Apps Script > Project Settings > Script Properties แล้วเพิ่มค่าต่อไปนี้

| Property | ค่า |
| --- | --- |
| `DATABASE_SPREADSHEET_ID` | ID ของ Google Sheet ที่สร้างไว้ |
| `FILES_FOLDER_ID` | ID ของโฟลเดอร์ Drive สำหรับไฟล์ |
| `INITIAL_ADMIN_USERNAME` | ชื่อผู้ใช้เริ่มต้นของผู้ดูแลระบบ |
| `INITIAL_ADMIN_PASSWORD` | รหัสผ่านชั่วคราวที่คาดเดายาก |
| `PASSWORD_PEPPER` | ค่าลับเสริมสำหรับ KDF (ไม่บังคับ แต่แนะนำให้กำหนดก่อน seed และห้ามเปลี่ยนโดยไม่มีแผนย้าย hash) |

ห้ามบันทึกค่ารายการเหล่านี้ลงใน source code, HTML, Git หรือเอกสารที่เผยแพร่ร่วมกับระบบ

## 3. สร้างและเตรียมฐานข้อมูล

1. เปิด Apps Script editor และเลือกฟังก์ชัน `setupSystem()` แล้วกด Run
2. ตรวจสอบว่า Google Sheet มี 29 แผ่นงานและ header ครบถ้วน
3. เลือกฟังก์ชัน `seedSystem()` แล้วกด Run การเรียกซ้ำจะไม่สร้างบัญชีหรือรายการ `SYSTEM_SEEDED` ซ้ำ
4. ตรวจสอบ `AuditLogs` ว่ามีรายการ `SYSTEM_SEEDED`

ทั้งสองฟังก์ชันเรียกซ้ำได้โดยไม่ลบแถวเดิม `setupSystem()` จะหยุดด้วย `CONFIG_MISSING` เมื่อไม่พบ Folder ID และ Drive จะส่งข้อผิดพลาดเมื่อ ID ใช้ไม่ได้หรือบัญชีไม่มีสิทธิ์ หาก header ของตารางที่มีข้อมูลไม่ตรงกับ schema ระบบจะหยุดและแจ้ง `SCHEMA_MISMATCH` เพื่อป้องกันข้อมูลเสียหาย

## 4. Deploy เป็น Web App

1. เลือก Deploy > New deployment > Web app
2. กำหนด Execute as เป็นบัญชีเจ้าของระบบ
3. จำกัด Who has access ตามนโยบายของโรงเรียน เช่น เฉพาะบัญชีในองค์กร
4. ตรวจสอบสิทธิ์ Google Sheets และ Drive ก่อนเผยแพร่ URL ให้ผู้ใช้

โครงการไม่ได้กำหนด anonymous access ใน `appsscript.json` และไม่ดำเนินการ deploy อัตโนมัติ

## 5. เข้าสู่ระบบครั้งแรกและเปลี่ยนรหัสผ่าน

1. เข้าสู่ระบบด้วย `INITIAL_ADMIN_USERNAME` และ `INITIAL_ADMIN_PASSWORD`
2. เปิดเมนู “ข้อมูลโรงเรียน” แล้วใช้ส่วน “เปลี่ยนรหัสผ่าน” ทันที รหัสผ่านใหม่ต้องมีอย่างน้อย 12 ตัวอักษร
3. ระบบจะเก็บรหัสผ่านด้วย PBKDF2-HMAC-SHA256 รูปแบบ `v3` ที่ระบุ work factor พร้อม salt และรองรับ pepper จาก Script Properties จากนั้นยกเลิก session อื่นของบัญชี การเปลี่ยน Users, Sessions และ AuditLogs จะ commit ภายใต้ transaction เดียว
4. ระบบไม่อนุญาตให้ hash รุ่นเก่าเข้าสู่ระบบผ่านหน้าเว็บ เพื่อป้องกันการแยกบัญชีจากเวลาตอบสนอง หากนำเข้าผู้ใช้จากระบบเดิม ให้ผู้ดูแลกำหนดรหัสผ่านชั่วคราวใหม่เป็น `v3` และบังคับเปลี่ยนรหัสผ่านในการเข้าสู่ระบบครั้งแรก
5. เมื่อตรวจสอบว่าเข้าสู่ระบบด้วยรหัสผ่านใหม่ได้แล้ว ให้ลบ `INITIAL_ADMIN_PASSWORD` ออกจาก Script Properties

## 6. การทดสอบ

ใช้ Node.js built-in test runner โดยไม่ต้องติดตั้งแพ็กเกจภายนอก

```powershell
npm test
node --check tests/core.test.js
```

ตรวจข้อมูลลับและข้อความค้างในโครงการด้วยคำสั่งจากแผนการพัฒนา ก่อนนำ source ไปใช้งานจริงควรทดสอบ integration กับสำเนา Google Sheet โดยเฉพาะ setup, seed, version conflict, session expiry และสิทธิ์ของทั้งสามบทบาท

## 7. แนวทางสำรองข้อมูลและสิทธิ์

- สำรอง Google Sheet ก่อนเปลี่ยน schema และเก็บสำเนาตามรอบเวลาของหน่วยงาน
- ให้สิทธิ์แก้ไขฐานข้อมูลเฉพาะผู้ดูแลที่รับผิดชอบ
- ตรวจ AuditLogs เป็นระยะ โดยเฉพาะการเข้าสู่ระบบ การเปลี่ยนการตั้งค่า และการเปลี่ยนสิทธิ์
- ห้ามบันทึกรหัสผ่าน session token หรือข้อมูลส่วนบุคคลลง console log
- การเข้าสู่ระบบของบัญชีที่ไม่พบ ปิดใช้ หรือใช้ hash รุ่นเก่าจะคำนวณ dummy PBKDF2 ก่อนส่งข้อผิดพลาดแบบเดียวกับรหัสผ่านผิด ตัวนับรายบัญชีและ token bucket ระดับระบบอัปเดตภายใต้ ScriptLock เพื่อจำกัดภาระจากชื่อผู้ใช้หมุนเวียน โดย bucket เติมคืนอัตโนมัติและไม่สร้างการล็อกบัญชีถาวร
- สำหรับการใช้งานจริงใน Google Workspace ควรกำหนด Web App ให้เข้าถึงเฉพาะผู้ใช้ในโดเมน หรือเปลี่ยนไปใช้ Google Identity เพื่อลดภาระการดูแลรหัสผ่านเอง หากเปิดสู่สาธารณะควรเพิ่ม challenge/CAPTCHA ที่ผ่านการทบทวนก่อนเปิดใช้งานจริง
- ห้ามแก้ URL ของโมดูลใน Sheet เพื่อเปลี่ยนเส้นทาง ระบบใช้ route จาก catalog ใน source code และยอมรับเฉพาะรูปแบบ `#/ชื่อเส้นทาง`
- ค่า `PASSWORD_KDF_ITERATIONS` เริ่มต้นเป็น 10,000 รอบ ต้อง benchmark ใน Apps Script deployment และบัญชีทดสอบจริงก่อนใช้งาน หากปรับ work factor ให้ทดสอบเวลา login/change-password และขีดจำกัด execution time โดยไม่ลดต่ำกว่าเกณฑ์ที่หน่วยงานยอมรับ
- เมื่อเปิดโมดูลเพิ่ม ต้องเพิ่ม contract test, permission test และ integration test ก่อนใช้งานกับข้อมูลจริง

## รายการที่ยังไม่รวม

รุ่นนี้ยังไม่มีการย้ายข้อมูลจากระบบเดิม การเชื่อม DMC, LINE หรือ Telegram เอกสาร ปพ.5/ปพ.6 ฉบับทางการ ฟอร์มเยี่ยมบ้านฉบับใช้งานจริง และการ deploy ไปยังบัญชี Google ของผู้ใช้
